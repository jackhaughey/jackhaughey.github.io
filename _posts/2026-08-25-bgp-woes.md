When trying to build a BGP lab that runs on Docker, my containers would not start.

I am trying to build a BGP lab using FRR containers, and having BGP run on them. Some research indicated that SElinux might be the culprit.
The fix was to add :Z to the mounts in my docker-compose.yaml file. Unfortuneately, this did not fix the issue. 
It turns out the fix was to use :z and not :Z
The difference is 
:Z = private label (exclusive to this container)
:z = shared label (multiple containers can read it)

The lab is using 3 containers, one for each router. Apparently SELinux will block :Z because it tries to give each container exclusive ownership.
This fixed the container failing issue. Now I have BGP failing to start. "Failed to start bgpd!"

The laptop I am using actually uses Podman under the hood, and pretends it's Docker. Which is fine most of the time.
Here there is an issue, as Podman is rootless, it does not provide the required capabilities to run, 
FRR requires these capabilities;
- CAP_NET_ADMIN
- CAP_NET_RAW
- CAP_SYS_ADMIN
- CAP_NET_BIND_SERVICE

The fix is to provide them in the docker-compose file;
cap_add:
 - NET_ADMIN
 - NET_RAW
 - SYS_ADMIN

Now BGP is running, I can continue with trying to build the lab.
